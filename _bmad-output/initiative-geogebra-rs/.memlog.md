- (requirement) R3 (prd FR-3): Compute first and second symbolic derivatives analytically for all supported differentiable functions
- (requirement) R4 (prd FR-4, Story 2): Compute and display real-time tangent line at point x0 synchronously during slider movement

- (requirement) R6 (prd FR-6, Story 3): Identify local extrema and inflection points with concavity change within active viewport

- (requirement) R12 (prd FR-12, Story 5, SM-3): Expose Axum REST endpoints for workspace save and retrieval returning short IDs within 50ms
- (constraint) Client compute: 100% of mathematical computation and rendering executes client-side via WASM and wgpu (prd Section 1, Section 5)
- (constraint) Rendering stack: Graphics pipeline targets WebGPU via wgpu with automatic WebGL2 fallback (prd Section 5, NFR-RELI-02)
- (constraint) Security: Mathematical expressions strictly parsed via AST parser; arbitrary code evaluation is prohibited (prd NFR-SECU-01)
- (constraint) Payload limit: Axum API payloads restricted to <= 64 KB and serialized workspace state under 10 KB (prd FR-11, NFR-SECU-02)
- (constraint) Numerical precision: Math evaluation conforms to IEEE 754 double precision with epsilon < 10^-12 (prd NFR-FUNC-01)
- (constraint) Performance budget: 60 FPS continuous navigation (< 16ms/frame), curve evaluation < 8ms for 2000 points, API persistence < 50ms (prd NFR-PERF-01, NFR-PERF-02, SM-1, SM-3)
- (constraint) Architecture decoupling: Math engine crate compiles independently of UI and web frameworks (prd NFR-MAIN-01)
- (assumption) Target user browsers support WebGPU natively or provide compatible WebGL2 support for wgpu (prd Section 11)
- (assumption) Axum persistence backend utilizes SQLite or lightweight storage without user authentication (prd Section 11)
- (assumption) Calculus curriculum focuses primarily on single-variable explicit functions y = f(x) on the Cartesian plane (prd Section 11)
